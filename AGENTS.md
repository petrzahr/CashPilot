# CashPilot

Client-only SPA for personal finance. No own backend: data is stored locally in the browser and synced to the user's Google Drive.

## Stack
- React 18.3 + TypeScript 5.7, entry `main.tsx` -> `App.tsx`
- State: React Context, mainly `FinanceContext.tsx`
- Icons: lucide-react; class composition: template literals with the shared recipes from `index.css`
- Styles: Tailwind CSS 4 via `@tailwindcss/vite` (no PostCSS config); the closed colour palette is the `@theme inline` block in `src/index.css`, reading the `--c-*` variables from `src/theme.css`
- Build: Vite 6 + `@vitejs/plugin-react` (`vite.config.ts`), npm
- Tests: Vitest, tests in `src/__tests__`
- Deploy: Vercel, `cashpilot.byzahr.app` (old `*.vercel.app` redirects there)

## Commands
- Installed packages and scripts: check `package.json` only (don't scan node_modules).
- Dev server: `npm run dev` (port 3000). Local launcher: `scripts/launcher.cjs` / `start.bat`.
- Build / regression check: `npm run build` (runs `tsc && vite build`). Must pass before every commit.
- Unit tests: Vitest via the test script in `package.json`.
- Sync cross-origin harness: `npm run test:sync-origins` - run whenever sync code changes.
- Icons are generated by `scripts/generateIcons.cjs` (sharp) - don't edit generated icons by hand.

## Key Files
- `src/context/FinanceContext.tsx` - central app state; runs the pure commands below and turns their outcomes into toasts and undo actions
- `src/services/transactionCommands.ts`, `accountCommands.ts`, `categoryCommands.ts`, `dataCommands.ts` - all data mutations as pure commands `(data, input, ctx) -> { data, outcome }`
- `src/services/accountScope.ts` - default account, effective amount, account flow
- `src/services/accountBalance.ts` - account balance at a date (liquid and asset accounts)
- `src/services/budgetBalances.ts` - budget screen balances: default account period totals and overdraft, day-group and per-source-account running balances
- `src/services/itemFilter.ts` + `src/hooks/useItemFilters.ts` - item list filtering shared by the budget and transactions screens
- `src/services/periodRange.ts` - period ranges for the Majetek and Analytics filters
- `src/services/storageService.ts` - local browser storage
- `src/hooks/useDriveSession.ts` - Google Drive session (SyncController lifecycle, connect/disconnect, Drive backups)
- `src/hooks/usePeriodForecast.ts` - today, current/selected period and navigation, Overview/Analytics ranges, memoised forecast; the forecast builds its own period sequence (`calculateForecast` in `financialEngine.ts`)
- `src/services/syncController.ts`, `src/services/syncModel.ts` - Google Drive sync logic; design in `docs/synchronization-v2.md` (read before changing sync)
- `src/services/driveBackupService.ts` - backups to a visible Drive folder
- `GLOSSARY.md` - domain terms used in code and reviews (default account, effective amount, account balance, command)
- `src/services/themeService.ts` - light/dark mode
- `src/theme.css`, `src/index.css` - design tokens and component recipes; rules in `DESIGN.md`

## Architecture Rules
- No backend. Don't propose server code, API routes or serverless functions unless I ask.
- Keep state in existing Contexts; don't add a state library (Redux, Zustand...) without approval.
- Don't duplicate state between Context and storage - storageService is the persistence layer.
- New data mutations go into a command module and are tested there directly; don't write domain logic inside `setData` updaters or test it by copying it into a test.

## Styling Rules
- Follow `DESIGN.md`. Use existing tokens from `theme.css` / `index.css`, no hardcoded colors or ad-hoc values.
- Every UI change must work in both light and dark mode (`themeService.ts`).
- Compose conditional classes with template literals; don't add a class-merging library (clsx, tailwind-merge) without approval.
- Icons only from lucide-react.

## Data & Sync Rules (high risk - user data)
- Any change to the stored data shape is a breaking change: propose a versioned migration and backward compatibility in the plan, and wait for approval.
- Never risk data loss: changes to sync, merge/conflict handling or backups require tests and `npm run test:sync-origins`.
- Google OAuth scopes are only `drive.appdata` and `drive.file`. Never add broader Drive scopes.
- Never log tokens or user financial data to the console.

## Security
- Strict CSP and security headers in `vercel.json`; allowed origins are only Google (accounts, googleapis) and Google Fonts.
- Don't add new external domains, CDNs, analytics or scripts. If something needs one, explain why in the plan and update the CSP only after approval.
- The OAuth client ID is public by design; there are no server secrets in this project.

## Bug Fixing
- Confine edits to the files actually causing the issue.
- Add or update a Vitest test reproducing the bug when practical.
- Verify with `npm run build` (and tests) before reporting the bug as fixed.

## Task Sessions
- One task = one session. When work turns up several independent tasks (e.g. three bugs found in a review), don't fix them in the current session: propose one session per task (a start-session card, `own_initiative`, context `fresh`), each with a self-contained brief: affected files, root cause or symptom, what done looks like.
- Only propose; never start sessions on your own. I start each one.
- Each task session runs in its own worktree (`use_worktree: true`) on a branch cut from `develop`, and follows the normal Plan First / approval flow inside that session.
- Quick follow-ups that only finish the current task stay in the current session.

## Git Workflow
- The base branch is `develop`. The main session works on `develop`; task sessions work on their own worktree branch cut from `develop` and commit there. Merge a task branch into `develop` only when I ask.
- After an approved task is implemented and `npm run build` passes, automatically:
  - Check changed files with `git status`.
  - Stage the changes and create a local commit on the current branch (Conventional Commits).
- Never run or ask about the git-release workflow.

## Context Preservation & File Exclusions
To conserve token limits and avoid context rot:
- Don't open or analyze:
  - Build output: dist/
  - Package dependencies: node_modules/
  - Lockfile: package-lock.json
  - Large binary/vector assets: *.svg, *.png, *.jpg, *.ico
- If dependency information is needed, refer only to package.json.

## Investigation Scope
- Start from files named in the prompt or stack trace, and read further only as far as the task requires.
- Keep explanations brief, and do not redesign for speculative edge cases.
